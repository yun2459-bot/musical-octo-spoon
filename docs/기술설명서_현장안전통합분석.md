# 1. 핵심 기능 — 텍스트마이닝 기반 점검 편향 분석

이 플랫폼의 중심 기능. **"점검을 많이 했는가"가 아니라 "고르게·실제 위험을 향해 했는가"** 를
측정한다. 네 개의 독립적인 관점으로 편향을 교차 검출한다.

### 1-1. 점검자별 위험분류 다양성 지수 (엔트로피 기반)

한 점검자가 특정 위험유형에만 쏠려 기록하는지를 **정규화 섀넌 엔트로피**로 측정한다.

```python
# scoring.py: inspector_bias()
p = g["위험분류"].value_counts(normalize=True)     # 점검자별 위험분류 비율분포
ent = -(p * np.log2(p)).sum()                      # 섀넌 엔트로피 H = -Σ p·log₂p
max_ent = np.log2(len(p)) if len(p) > 1 else 1     # 최대 엔트로피 log₂(k)
norm_ent = ent / max_ent                           # 0~1 정규화
```

$$\text{다양성지수} = \frac{-\sum_{i} p_i \log_2 p_i}{\log_2 k}$$

- $p_i$ = 해당 점검자의 전체 지적 중 위험분류 $i$의 비율, $k$ = 실제로 다룬 위험분류 종류 수
- **0에 가까울수록 특정 위험에만 편중**, 1에 가까울수록 고르게 점검
- 최소 표본 `min_count=10`건 미만 점검자는 산출 제외 (소표본 왜곡 방지)
- 대상 분류: 물리위험 10종 + 관리적미흡 + 정리정돈
- **질병성 재해(무리한동작·질병)는 기본 제외** (`exclude_disease=True`)
- 부가 출력: 최다위험 유형, 최다비중(%), 다룬 위험종류 수
- 드릴다운(`inspector_detail()`): 해당 점검자가 **전혀 다루지 않은 물리위험 목록**을 역산해 제시

### 1-2. 갭분석 — 점검 비중 vs 실제 사고 비중

점검 활동의 분포가 실제 사고 발생 분포와 얼마나 어긋나는지 비교한다.

```python
# scoring.py: coverage_gap(), coverage_gap_by_branch()
ins = insp[...]["위험분류"].value_counts(normalize=True) * 100        # 점검 비중(%)
acj = acch[...]["점검관련위험"].value_counts(normalize=True) * 100    # 사고 비중(%)
df["갭(사고-점검)"] = (df["사고비중"] - df["점검비중"]).round(1)
```

$$\text{Gap}_h = \left(\frac{n^{\text{사고}}_h}{\sum_j n^{\text{사고}}_j} - \frac{n^{\text{점검}}_h}{\sum_j n^{\text{점검}}_j}\right) \times 100$$

- **갭(+)** = 사고는 나는데 점검이 적음 → 사각지대 후보
- **갭(−)** = 점검 대비 사고가 적음 → 과잉점검이 아니라 예방 효과일 수 있어 단정하지 않음
- 전사(`coverage_gap`)·지사별(`coverage_gap_by_branch`) 양쪽 제공

**사고 비중 산출의 핵심 보정** — `safety_accident_hazard()`:
사고 데이터 2,058건 중 인적재해는 425건뿐이라 인적재해만 보면 화재·풍수해가 0으로 보인다.
그래서 인적재해(상해유형 기반) + **비인적 사고까지 키워드로 스캔한 화재·폭발·풍수해**를 합산한다.

```python
FIRE_PAT    = "화재|폭발|발화|연소|화염|불꽃"
WEATHER_PAT = "풍수|태풍|호우|침수|강풍|폭우|폭설|해일|낙뢰|동파"
# 인적재해 → 상해유형 기반 위험분류 사용
# 비인적재해(재물·기타) → 사고유형1+사고유형2+사고개요 텍스트에서 키워드 매칭
```

### 1-3. 점검 사각지대 판정

```python
# scoring.py: blind_spots(insp, acc, recent_days=180)
```

| 조건 | 판정 |
|---|---|
| 과거 인적재해 ≥ 2건 **AND** 최근 180일 점검 = 0건 | 🔴 사각지대 |
| 과거 인적재해 ≥ 3건 **AND** 최근 180일 점검 ≤ 1건 | 🟡 점검부족 |
| 질병성(무리한동작 등) & 과거재해 ≥ 2건 | 🟣 질병성(별도관리) |

- 기간 기준: `insp["점검일자"].max()` 로부터 역산 180일 (고정 달력일 아님)
- **질병성 분리가 핵심 설계**: 근골격계는 작업 후 질병으로 판정되는 지연발현형이라
  현장 실시간 점검으로 포착이 구조적으로 어렵다. 이를 "사각지대"로 부르면 안전관리자를
  부당하게 탓하는 것이 되므로, 별도 트랙(유해요인조사·인간공학 개선)으로 분리한다.
  → `HAZARD_TRAIT = {"무리한동작": "질병성", "질병": "질병성", ...}`

### 1-4. 동적 워드클라우드 — 급증 위험요인 탐지

지적내용·조치내용 텍스트에서 **최근 60일 vs 직전 60일** 빈도 변화율로 색상을 입힌다.

```python
# app.py: growth_wordcloud()
recent = df[df["점검일자"] >= end - 60일]
prior  = df[(df["점검일자"] < end - 60일) & (df["점검일자"] >= end - 120일)]
growth = {w: (fr.get(w,0) - fp.get(w,0)) / (fp.get(w,0) + 1) for w in total}
```

$$g_w = \frac{f^{\text{최근60일}}_w - f^{\text{직전60일}}_w}{f^{\text{직전60일}}_w + 1}$$

| 증가율 | 색상 | 의미 |
|---|---|---|
| $g_w \ge 1.0$ | 🔴 `#d62728` | 급증 |
| $0 < g_w < 1.0$ | 🟠 `#e8862c` | 증가 |
| $g_w \le 0$ | ⚪ `#7f8fa6` | 안정 |

- 분모 `+1`은 직전 기간 빈도 0인 신규 단어의 0-division 방지 겸 과대평가 억제
- 크기는 전체 기간 누적 빈도, 색상은 증가율 → **"많이 나온 말"과 "새로 늘어난 말"을 분리 표현**
- 지적내용/조치내용 2개로 분리 표시 (무엇을 지적했나 / 어떻게 개선했나)
- `max_words=30` 제한 (식별성 확보)

> ⚠️ **정확히 밝힐 점**: 이 워드클라우드의 토크나이저는 **형태소 분석기가 아니라 정규식**이다.
> `re.findall(r"[가-힣]{2,}", text)` + 불용어 약 100개(문법조각·점검 메타어·지명 11개 지사명 등).
> 형태소 분석기(kiwipiepy)는 아래 1-5의 **단어 위험도 사전 구축 파이프라인에서만** 사용한다.

### 1-5. 형태소 분석 기반 단어 위험도 사전 (별도 파이프라인)

`extract_words.py` → `classify_words.py` 2단 파이프라인.

**① 형태소 분석 및 문법역할 태깅** (`extract_words.py`, kiwipiepy)

```python
NOUN_TAGS       = {"NNG", "NNP"}                    # 일반명사·고유명사
VERB_MARK_TAGS  = {"XSV", "VV", "VA", "XSA"}        # 동사·형용사 어간
SUBJ_PARTICLES  = {"JKS"}   # 주격조사 → 뒤따르면 '주어'로 태깅
OBJ_PARTICLES   = {"JKO"}   # 목적격조사 → 뒤따르면 '목적어'로 태깅
```

- 명사 뒤 조사를 보고 **주어/목적어/명사** 역할 판정, 용언 어간은 **동사**로 태깅
- 결과: 고유 (단어, 역할) 조합 **1,883개**, 빈도 2회 이상 **1,092개**

**② 위험도 산정 — 절대 기준점 공식** (`classify_words.py`)

$$\text{단어 위험강도} = S_i \times R_j$$

| 위해도 $S_i$ (재해유형 상수) | 값 |
|---|---|
| 추락, 화재·폭발, 질식 | 4.0 |
| 감전, 끼임·협착, 낙하·비래·붕괴, 전도 | 3.0 |
| 충돌, 온열·온도, 무리한동작 | 2.0 |
| 그 외(관리적미흡·정리정돈·보호구·일반) | 0.0 |

| 역할가중치 $R_j$ (문법·의미역 상수) | 값 |
|---|---|
| 위험행위·현상 | 1.0 |
| 장비시설물 | 0.8 |
| 위치구조 | 0.5 |
| 안전조치·보호구 | 0.2 |
| 일반·무관어 | 0.0 |

- **곱셈 구조 선택 이유**: 위해도 0인 유형(관리적미흡 등)은 역할과 무관하게 0이 되어야 함.
  덧셈이면 위해도 0인데도 역할 가중치만으로 양수가 나와 원치 않는 결과 발생.
- **3단 우선순위**: ① 동의어 매핑 사전 → ② WORD_RISK 사전(525단어) → ③ OOV는 `일반/0.0` 안전 기본값
  (신규 단어 유입 시 임의 조율 금지 = 시계열 일관성 보장)
- **N-gram 문맥 규칙 엔진 7개**: 타겟어 주변 조건어 매칭 시 점수 보정
  (예: `안전난간`+`미설치|파손` → 최고위험 강제 / `치여`+`똥|장난` → 0.0 무효화(비산업재해 오탐 제거))

**③ 외부 코퍼스 준거타당도 검증**

안전보건공단 산업안전포털에서 실제 사고사례 **601건**(제목 481 + 발생개요 120)을 수집해,
사전의 분류가 실제 그 위험유형 문맥에서 쓰이는지 자동 교차검증.

| 위험분류 | 일치율 | | 위험분류 | 일치율 |
|---|---|---|---|---|
| 추락 | **82.4%** (398/483) | | 감전 | 45.9% (39/85) |
| 끼임·협착 | 58.2% (96/165) | | 질식 | 44.7% (21/47) |
| 화재·폭발 | 57.9% (73/126) | | 전도 | 41.7% (40/96) |
| 낙하·비래·붕괴 | 41.7% (215/516) | | 충돌 | 36.4% (40/110) |
| **전체** | **56.5%** (922/1,633) | | 무리한동작 | 0% (0/5)※ |

※ 무리한동작 0%는 오분류가 아니라 **검증 불가**. KOSHA "업무상 사고사례" 게시판이 급성사고만
다루고 만성 질병(근골격계)은 취급하지 않아 검증할 자료 자체가 없었음.

검증 결과 실제 반영: **"산소"를 질식 → 화재·폭발로 재분류** (코퍼스 8건 전부 산소절단·산소용접·

### 1-6. 위험분류 오분류 탐지 (지사 간 라벨링 일관성 점검)

LLM이 지적내용 원문을 읽고 **점검자가 붙인 위험분류 라벨과 실제 내용이 불일치하는 사례**를 검출.
현재 6건 검출. 실무적 의미: *"안전모 미착용"* 같은 동일 현상을 어떤 지사는 `보호구`,
다른 지사는 `관리적미흡`으로 기록하는 **입력 편향**을 드러낸다. 이는 갭분석의 신뢰도를
떨어뜨리는 근본 원인이므로, 편향분석의 전제조건 점검에 해당한다.

### 3-2. 전처리 로직

**① 대상 레코드 선별** — 코칭명(제목)은 지사마다 표기가 달라("안전관리자 점검일지" vs

```python

```

**② 지사 귀속 기준**: `코칭부서`(코칭 수행자 소속)가 아니라 **`조치부서`**(실제 시정조치 대상)를

### 개발 방식

안전보건 도메인 전문가가 **AI 코딩 도구(Claude)를 활용해 직접 설계·구현·운영**한 프로젝트다.
역할 구분은 다음과 같다.

| 구분 | 내용 |
|---|---|
| **본인(도메인·설계)** | 문제 정의(점검 편향 자가진단), 위험분류 taxonomy 설계, 지표 해석 기준 수립, 데이터 확보·검수, 방법론적 의사결정(질병성 재해 분리, 처벌 아닌 자원배분 프레이밍, 심각도 예측모델 배제 원칙), 현장 피드백 수집·반영, 배포·운영 |
| **AI 도구** | 위 설계에 따른 코드 구현, 정규식·알고리즘 작성, 디버깅 보조 |

> 6주 만에 정제 파이프라인·분석 로직·대시보드·외부 시스템 연동·배포까지 도달할 수 있었던 것은
> 이 방식 덕분이며, **도메인 판단이 필요한 지점**(근골격계를 사각지대에서 제외한 결정,
> 사고 심각도 학습을 안전 원론에 따라 배제한 결정, 조치부서 기준 귀속 등)은 모두
> 안전보건 지식에 근거해 직접 판단·검증했다.

### 주요 방향 전환

**① 대시보드 구조 4탭 → 2탭 → 3탭(복구)**
"데이터가 너무 많아 보기 어렵다"는 현장 피드백으로 대폭 축소했다가, 그 과정에서
**편향분석 탭 전체가 사라진 것을 발견하고 복구**. 이 프로젝트의 존재 이유가
"안전관리자의 점검 편향 자가진단"이었으므로, 단순화하더라도 핵심 축은 훼손하면 안 된다는
기준을 이때 확립.

**② 위험지수 프레이밍 전환 (처벌 → 자원배분)**
지사별 위험지수는 점검을 열심히 할수록 올라가는 구조라, 그대로 두면 **성실한 지사가 불리해 보이는
역인센티브**가 생긴다. → ⓐ 대시보드 전면에 해석 가이드 배너 상시 노출, ⓑ **'양(건수) vs 질(평균심각도)'
산점도**로 분리 표현, ⓒ 총량/사업장당/관리자당 3종 정규화 토글 제공.

**③ 근골격계 해석 교정 (사각지대 → 질병성 별도관리)**
초기 분석에서 "무리한동작: 사고비중 14%인데 점검 0% → 최대 사각지대"로 판정했으나,
근골격계는 **지연발현형 질병**이라 현장 실시간 점검으로 포착 불가능하다는 도메인 지식을 반영해
별도 트랙으로 재설계. 데이터가 말하는 것을 그대로 옮기면 잘못된 결론에 이르는 사례.

**④ 심각도 산정 방법론 전환 (주관 점수 → 공식 기반)**
단어별 위험도를 사람이 직관적으로 1~4점 매기던 방식을 $S_i \times R_j$ 공식으로 전면 교체.
신규 단어 유입 시에도 임의 조율 없이 동일 공식이 적용되어 시계열 일관성 확보.

### 막혔던 지점과 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 사내 시스템 로그인 거부 ("정상적인 경로로 접근하지 않았습니다") | 서버가 Referer/Origin 헤더로 봇 판별 | 로그인·내보내기 POST에 `Referer`/`Origin` 헤더 명시 |

| 전체 이력 백필 시 데이터 누락 | 페이지 크기 1000 고정인데 전체 1,784건 | 페이지 크기 상향 + **총건수 파싱 정규식 오류**(`</i></a>건의` 사이 태그) 수정해 잘림 감지 경고 추가 |

| 지사 점검 데이터 일부 누락 | 코칭명 텍스트 필터(지사마다 표기 상이) | **구조적 필드 조건**(점검유형+조치부서 패턴)으로 교체 |
| Streamlit 화면에 코드/객체가 출력됨 | 삼항연산자를 문장으로 사용 → magic 출력 | 명시적 `if/else` 블록으로 전환 (2회 재발, 회귀 지점으로 기록) |
| PII 마스킹 확장 시 일상어 대량 훼손 | 사고자 명단에 회사명·장비명 오탐 혼입("지게차" 68건) | 사고용/점검용 **매핑 스코프 분리** |

# 7. 한계 및 알려진 제약

### 방법론적 한계 (`docs/RESEARCH_METHODOLOGY_LOG.md`에 기록)

1. **$S_i$·$R_j$ 상수의 통계적 근거 부족** — 고용노동부 "재해조사 대상 사망사고 발생현황"
   (2024·2025)으로 **상대 서열**(추락 38.5~44.9% > 낙하·비래 13.6~14.1% > 끼임 9.4~11.2% >
   충돌 8.5~9.8%)이 공식 통계와 일치함은 확인했으나, **절대값 4.0/3.0/2.0의 근거는 미확보**.
   화재·폭발/질식/감전/온열은 정부 통계 상위 5개 유형에 없어 검증 불가. **전도**는 정부 분류에
   대응 범주가 없어 매칭 실패. → **미해결**

2. **단어 분류 검증이 1인 검토 수준** — 복수 평정자 독립 코딩·평정자간 신뢰도(Cohen's Kappa)
   미실시. AI 1차 판정 → 사용자 1인 승인 구조. → **미해결**

3. **외부 검증 코퍼스가 편의표집** — KOSHA 게시판 최신순 도달분만 수집(제조업 1,448건 중 158건,
   10.9%). 무작위표집 아님. 대부분 사망사고라 경미사고 어휘 과소표집. 이용약관·공공누리 조건
   미확인. → **논문 인용 시 한계 명시 필요**

4. **준거타당도 56.5%의 해석 주의** — "익사"(추락 분류)처럼 결과어는 원인 동작이 문장에
   재언급되지 않아 인위적 저평가. 방법의 한계이지 분류 오류가 아닐 수 있음.

### 데이터·구조적 제약

5. **점검 데이터 기간 7개월(2026-01~07)** — 계절성 분석·연간 추세 판단 불가.
   워드클라우드 급증 판정(60일 vs 60일)도 표본이 얇음.

6. **공정·설비 마스터 데이터 부재** — 현재는 *"이 사업장을 안 봤다"* 와
   *"애초에 그 위험이 없는 사업장이다"* 를 구분할 수 없음. 사각지대 판정의 근본 한계.

7. **LLM 하이브리드 커버리지 785/1,047건** — 직접판정은 195건뿐이며, 이후 증가분은
   `미적용(신규점검)` 처리. 전체 확장 미결정.

8. **워드클라우드 토크나이저가 형태소 분석기 아님** — 정규식 + 불용어 방식이라 조사·어미
   분리가 불완전. (사전 구축 파이프라인은 kiwipiepy 사용)

9. **재해 심각도 예측 모델 없음 — 의도적 배제** — "재해의 정도는 우연"이라는 안전 원론에
   따라, 개별 사고 결과의 심각도를 종속변수로 학습하는 회귀·예측 모델은 **설계 단계에서 배제**.
   또한 사고 데이터에 심각도 연속변수(휴업일수·장해등급)가 없고 인적재해 425건으로 표본도 부족.

10. **테스트 커버리지 제한적** — pytest 12개(`test_scoring.py`, `test_mask_pii.py`)로
    핵심 산출식·마스킹 회귀만 커버. `app.py`·`heatwave.py`는 자동 테스트 없음.
